# 高性能 MySQL（Baron Schwartz 等）

来源：[本地]（未联网确证）· 用途：MySQL/InnoDB 性能与运维操作手册。

## 方法论

- **优化目标顺序**：先减少响应时间，再减少资源消耗；瓶颈定位用「剖面 → 优化 → 度量」闭环。
- **等待分析**：查询耗时 = 服务时间 + 排队时间；关注锁等待、IO 等待、CPU 上下文切换。
- **基准测试**：sysbench / mysqlslap；变更须可复现、有对照组。

## 关键章要点

| 主题 | 判据 |
|---|---|
| Schema | 小而合适的列类型；`NOT NULL` + 默认值；避免 `TEXT/BLOB` 滥用；自增 vs UUID 主键写放大 |
| 索引 | 最左前缀、覆盖索引、索引条件下推（ICP）；避免冗余/重复索引；前缀索引选择度 |
| 查询 | `EXPLAIN` 看 type/key/rows/Extra；避免函数包裹索引列、隐式转换、`SELECT *` |
| 分区表 | 按范围/列表分区利于归档；分区键须含于主键 |
| 复制 | 基于语句 vs 基于行（ROW 更安全、binlog 更大）；并行复制与延迟监控 |
| 扩展 | 读写分离、分库中间件；连接池（应用侧 vs 代理侧 ProxySQL） |
| InnoDB | 缓冲池、redo/undo、change buffer、双写；`innodb_flush_log_at_trx_commit=1` 才满足持久性 |

## 用法

1. 慢查询治理按本书顺序：开关与阈值 → 剖面 → `EXPLAIN` → 索引/改写 → 复测。
2. 参数变更属高危：先备份配置、给出回滚值，记入逻辑链。
