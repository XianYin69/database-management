# 设计数据密集型应用（DDIA · Martin Kleppmann）

来源：[本地]（未联网确证）· 用途：可靠性/可扩展性/可维护性权衡语言。

## 三条主线

- **可靠性**：故障是常态；正确性 = 系统假设 + 不变量；背压、幂等重试、超时与级联失败。
- **可扩展性**：负载指标（QPS/数据量/基数）→ 分区（键范围/哈希/一致性哈希）→ 再平衡；
  复制（主从/多主/无主 quorum）与滞后读。
- **可维护性**：可操作（观测/编排）、可理解（模型清晰）、可演进（schema 变更与兼容）。

## 高频概念（本技能直接引用）

| 概念 | 判据 |
|---|---|
| 编码格式 | 模式文件/内嵌/自描述；兼容 = 新增可选字段 |
| 存储引擎 | LSM 写优化 vs B 树读优化；压缩与合并代价 |
| 事务 | 单对象原子性 vs ACID；因果序与线性化 |
| 副本一致性 | 最终一致 / 读己写 / 单调读 / 前缀一致 |
| CDC 与事件溯源 | 变更日志作为集成总线；派生状态可重建 |
| 批与流 | 物化视图、窗口与时区、时钟不可信 |

## 用法

1. 需求确认阶段用「可靠性/可扩展性/可维护性」三问定优先级，避免默认堆架构。
2. 分区键与复制方式的选择必须写进大纲并留逻辑链（决策可追溯）。
3. 「写优化 vs 读优化」选型对照 LSM/B 树代价，见 [索引进阶](../性能与索引/索引进阶.md)。
