# 索引进阶（B-tree / B+ / 哈希 / GIN / GiST / BRIN / LSM）

来源：[本地]（未联网确证）· 用途：索引选型与代价评估。

## 结构对比

| 结构 | 适用谓词 | 写代价 | 备注 |
|---|---|---|---|
| B-tree / B+ | 等值、范围、排序、前缀 | 中 | 默认选择；叶子链表利于范围扫 |
| 哈希 | 仅等值 | 低 | 不支持范围/排序（PG hash 索引） |
| GIN | 多值/全文/`jsonb`/数组包含 | 高（插入慢） | 可 `fastupdate`；回表代价大 |
| GiST | 地理/范围/排除约束/近似 | 中 | 非平衡、可 lossy 需 recheck |
| BRIN | 天然有序大表（时间/自增） | 极低 | 块级摘要，选择度依赖物理有序 |
| LSM | 高写入吞吐 | 写低读高 | 读放大 + 压缩；与 B 树相反取舍 |

## 设计规则

1. **最左前缀**：复合索引列序按「等值列 → 范围列 → 排序列」；跳过中间列即失效。
2. **覆盖索引**：把投影列纳入索引避免回表；但索引变宽 → 写放大与缓存占用上升。
3. **选择性**：低基数列（性别/状态）单独建索引通常无用，宜作复合索引尾列或部分索引。
4. **表达式索引**：函数包裹列查询须建表达式索引，否则退化为全扫。
5. **索引预算**：写多读少的表索引数上限评审；重复/冗余索引定期清理。
6. **统计**：`ANALYZE`/autovacuum 保证直方图新鲜，否则优化器错估连接顺序。

## 判据

- 慢查询治理顺序：能否用现有索引 → 复合索引列序 → 覆盖 → 部分/表达式 → 改写查询。
- 新增索引须给出预估收益（行数下降倍数）与写放大影响，并留逻辑链。
