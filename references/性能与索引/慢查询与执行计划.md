# 慢查询分析与执行计划（EXPLAIN / 剖面 / 改写）

来源：[本地]（未联网确证）· 用途：性能问题定位流程。

## 采集

- 开关：MySQL `slow_query_log`（`long_query_time`、`min_examined_row_limit`）、
  `log_queries_not_using_indexes` 慎用（噪声）；PG `log_min_duration_statement`、
  `auto_explain`；通用 `pg_stat_statements` / Performance Schema。
- 剖面：按「总耗时 × 次数」排序，先攻最贵的少数查询（80/20）。

## 读执行计划

| 信号 | 含义 | 动作 |
|---|---|---|
| 全表扫 / 大 `rows` 估算 | 无可用索引或谓词不可 sargable | 建索引或改写谓词 |
| `type=ALL`（MySQL） | 无索引连接 | 加索引或改连接顺序 |
| Nested Loop × 大行数 | 驱动表选错 | 统计更新 / 改写 / hint 验证 |
| Sort / Temp table on disk | 内存不足或 `ORDER BY` 无索引 | 覆盖索引、减小结果集 |
| `Using filesort`/`Using temporary` | 排序未走索引 | 调整索引列序 |
| 估算与实际偏差 >10× | 统计过期 | `ANALYZE` |
| ICP / Index Cond 缺失 | 谓词下推失败 | 去函数包裹、避免隐式转换 |

## 改写清单

1. 只取所需列，禁 `SELECT *`；分页用键集（seek）替代深 `OFFSET`。
2. 把函数/CAST 移出索引列；统一字符集与排序规则避免隐式转换。
3. 大 `IN` 列表 → 临时表/JOIN；`OR` → UNION ALL 或条件索引。
4. N+1 查询 → 批量取或 JOIN；跨库关联 → 应用层组装或 CDC 冗余。
5. 每次改写须有前后对比数据（耗时、行数、缓冲命中），记入逻辑链。
