# 分库分表与读写分离（扩展路径与代价）

来源：[本地]（未联网确证）· 用途：扩展方案评审。

## 先垂直后水平

1. 索引/SQL 优化 → 2. 缓存与读写分离 → 3. 单库分区/归档 → 4. 垂直拆分（按业务域）→ 5. 水平分片。
跳步水平分片是常见错误：复杂度（跨片事务、聚合、分页、全局唯一）远高于收益。

## 读写分离

- 路由：写主、读从；按语句特征（事务内、`FOR UPDATE`、刚写完的读）强制走主。
- 复制延迟导致「读不到自己刚写的」→ 需读己写保证：会话粘性、等待 binlog/LSN 位点、或强制主库。
- 从库故障摘除与健康检查、连接权重、延迟阈值（`Seconds_Behind_Master` / `replay_lag`）。

## 水平分片

| 维度 | 选项与判据 |
|---|---|
| 分片键 | 查询主维度；避免热点（时间前缀自增键易倾斜） |
| 算法 | 哈希（均匀、扩容需再平衡）、范围（利于区间扫、易热点）、一致性哈希（减再平衡） |
| 全局唯一 ID | 号段 / UUIDv7 / 雪花（时钟回拨须处理） |
| 跨片查询 | 广播 + 应用层聚合；异构索引表（基因法/映射表）解决非分片键查询 |
| 扩容 | 双写迁移 + 校验 + 灰度切读；避免一次性 rehash |
| 中间件 | 客户端分片 vs 代理层；事务与 SQL 解析能力差异须实测 |

## 判据

1. 分片方案必须写明：分片键、热点评估、扩容路径、跨片查询清单，缺项驳回。
2. 跨片强一致事务默认禁止；确需则改为 saga/最终一致 + 对账任务。
3. 迁移期双写必须有对账与回切开关（见 [备份恢复与PITR](备份恢复与PITR.md)）。
