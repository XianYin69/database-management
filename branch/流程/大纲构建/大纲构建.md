# 大纲构建
把需求拆成模型、迁移与访问接口，形成可审阅的实现大纲。
## 动作
1. 列对象：表/视图/索引/约束/迁移序列/访问层/作业（回填、归档、校验）。
2. 定接口：查询签名与参数、返回列、错误与重试约定（可重试码 vs 不可重试）。
3. 定布局与命名：`migrations/V0001__topic.sql`、`src/`、`tests/`（准则见 [dependence/](../../../dependence/dependence.md)）。
4. 标风险点：破坏性 DDL、大表回填、锁与 MDL、复制延迟、精度与时区，供分支分析与浏览器学习消费。
5. 写明回滚：每个变更的 down 路径或恢复点位；不可回滚项单独标注。
6. 大纲交用户审阅确认后再进入分支分析；确认结论写逻辑链。
## 产出
- `tmp/outline.md`：对象表 + 接口表 + 迁移序列 + 风险与回滚清单（≤50 行，超则拆子文档）。
- 每对象一条 `process_chain.py save --step 大纲构建 --data '{"object":"..."}'`。
## 兜底
- 大纲与需求冲突：回 [需求确认](../需求确认/需求确认.md) 重澄清，禁止私自缩减范围。
- 规模过大：先切 MVP 子集（核心表 + 关键查询）交付，其余列 TODO 并告知用户。
