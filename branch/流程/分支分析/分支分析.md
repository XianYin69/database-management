# 分支分析
对大纲的每个岔路做正反双链自辩，再定引擎/模型/扩展性分支。
## 分析维度
1. **引擎与版本**：PostgreSQL / MySQL / SQLite / Redis / MongoDB 的取舍（许可、运维成本、团队栈）。
2. **数据模型**：关系 / 文档 / 宽列 / 键值 / 图，按访问模式而非偏好选择（见 [`references/数据建模/`](../../../references/数据建模/NoSQL数据模型.md)）。
3. **一致性与隔离**：隔离级别、锁策略、幂等与重试（见 [`references/理论基础/`](../../../references/理论基础/ACID与隔离级别.md)）。
4. **扩展路径**：读写分离 / 分区 / 分片 / 归档，先垂直后水平（见 [`references/可用性与演进/`](../../../references/可用性与演进/分库分表与读写分离.md)）。
5. **风险分支**：破坏性 DDL、大表回填、锁等待、复制延迟、精度与时区、字符集隐式转换。
## 动作
- 每个岔路一次辩论：`python -B scripts/logic_chain.py debate --pro <正方> --con <反方>`，裁决记逻辑链。
- 结论落 `tmp/branch-decision.md`：选项、裁决、理由、被否方案、影响的数据量级。
- 任一维度信息不足（引擎某版本行为、参数默认值）→ 立即转 [浏览器学习](../浏览器学习/浏览器学习.md)。
## 兜底
- 双链势均：选约束表达更强、回滚更容易的一支，并记 TODO 复验。
- 无法确证引擎行为时，禁止按类推写实现；降级为「只出方案不出代码」并告知用户。
