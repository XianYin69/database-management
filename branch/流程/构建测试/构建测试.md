# 构建测试
迁移可跑、约束生效、查询有证据才算完成，失败即回脚本构建。
## 动作
1. 预览：`python -B scripts/run_tests.py --path tmp/<proj> --dry-run`，确认后执行。
2. 迁移链验证：临时库跑 `up → down → up`，记录耗时与失败点（`schema_migrate.py` 台账）。
3. 约束验证：逐条构造违反用例（重复键、孤儿外键、空值、越界、精度）确认被数据库拒绝。
4. 数据用例：种子数据 + 幂等重放 + 并发写（锁等待/死锁重试路径）。
5. 性能证据：关键查询 `EXPLAIN` 存档，`slow_query_check.py --explain` 出退化信号清单。
6. 备份证据：`backup_verify.py --dir tmp/backup` 核验大小/新鲜度/格式头。
7. 失败处理：最小可复现片段 → `process_chain.py interrupt` → 回 [脚本构建](../脚本构建/脚本构建.md) → `resume`。
## 产出
- `tmp/test-report.md`：用例数、通过率、迁移耗时、约束拒绝清单、执行计划结论。
- 逻辑链一条：测试结果 → 是否可交付的裁决。
## 兜底
- 无临时库可用：降级为静态校验（sql_lint + 迁移台账预演）并明确告知「未做真库验证」。
- 报错原因不明 → 转 [浏览器学习](../浏览器学习/浏览器学习.md) 查错误码，禁止猜测式反复改。
- 重试达 10 次：`penalty.py hit` 熔断，回退本步或求助用户。
