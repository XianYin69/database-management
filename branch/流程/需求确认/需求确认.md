# 需求确认
接收数据任务后先澄清，再动手；区分创建 or 修改。
## 必答清单
1. **数据形态**：实体与关系、读写比例、现有 schema 或样例数据。
2. **引擎与版本**：PostgreSQL/MySQL/SQLite/Redis/MongoDB 及具体版本、部署形态（自建/托管）。
3. **规模与性能**：行数与增速、QPS、时延上限、并发与事务特征、数据保留期。
4. **一致性与持久性**：可容忍的隔离级别、RPO/RTO、是否允许最终一致。
5. **验收标准**：可执行的测试或判据（约束生效、迁移可回滚、查询耗时阈值；无判据＝需求未确认）。
6. **路径判定**：新建库/表/迁移体系 → 创建流程；改既有 schema/脚本/技能 → 修改流程。
## 动作
- 缺项一次一问向用户确认（`ask_user`），禁止用假设填补关键需求（尤其引擎版本与破坏性操作范围）。
- 每条判定写逻辑链：`python -B scripts/logic_chain.py add logic_chain.jsonl --from 需求确认 --to <判定> --why <理由>`。
- 存档：`python -B scripts/process_chain.py save --step 需求确认 --data '{"...": "..."}'`。
## 兜底
- 用户不响应或需求持续模糊：出流程图辅助澄清（`scripts/flowchart_helper.py`），仍不明则熔断求助。
- 无法确知数据量级：按最坏量级评估锁与迁移时长，并在大纲标注假设。
