# 脚本构建
按大纲与分支裁决写 schema/迁移/访问代码；本体薄，规范与范式经依赖获取。
## 动作
1. 脚手架：`python -B scripts/scaffold_project.py --target tmp/<proj> --layout migrations,src,tests`。
2. DDL/迁移：一版本一文件 `V0001__topic.sql`（含 up/down），命名与台账用
   `python -B scripts/schema_migrate.py --migrations tmp/<proj>/migrations --state tmp/state.json`。
3. 静态体检：`python -B scripts/sql_lint.py tmp/<proj>/migrations`，错误清零才进构建测试。
4. 访问层：调用 [code-guidelines](../../../dependence/dependence.md) 取命名/复杂度准则，
   [pavedpath-code](../../../dependence/dependence.md) 取已验证范式；参数化查询，禁字符串拼接 SQL。
5. 脚本不限行数（50 行红线只约束 markdown）：超长函数即拆「入口脚本 + 模块」，禁裸 except、print 调试残留、>100 字符长行。
6. 每步提交功能分支 `feature/<topic>`（见 git 工作流约束）。
## 禁止
- 臆造 SQL/引擎行为：任何不确定语法、参数默认值、DDL 是否在线，须经
  [浏览器学习](../浏览器学习/浏览器学习.md) 取证。
- 放宽约束图省事（见 [数据完整性约束](../../../resistance/数据完整性约束/数据完整性约束.md)）。
- 未附回滚的破坏性 DDL（见 [迁移安全约束](../../../resistance/迁移安全约束/迁移安全约束.md)）。
- 静默写盘：默认 `--dry-run`，落盘须显式 `--yes`。
